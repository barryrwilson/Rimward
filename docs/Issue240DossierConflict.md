## Outcome and single scenario

A newly posted **Shadow courier — exclusive Ledger dossier** at **Ledger Anchorage, The Redmarch** (`originSystem: redmarch`) still sends the pilot to the same named courier in **Veridian Reach** (`destSystem: veridian`). Red Ledger commissions the complete corroborated route/traffic dossier exclusively. **Veridian Combine**, at **Veridian Spire**, offers more for that exact completed dossier and its exclusive ownership. No other station, faction pairing or mission acquires conflict behavior.

The original offer states exclusivity BEFORE acceptance. The ordinary basic report remains a useful safe exit, payable only to the original employer through the existing path. The competing buyer purchases only a completed dossier, never basic or partial evidence. Exclusivity is attached to this one accepted assignment, not to employment with either faction generally. Taking unrelated work, accepting a Veridian introductory job, docking at Veridian, inspecting the offer, closing a pane, or not answering never betrays anyone.

Display the courier's existing unique name, original job ID and a short dossier reference together: **Complete route dossier: <courier> · <job ID> · <first 8 token characters>**. This refers to the player's corroborated observations, not cargo, secret intent, a generic commodity or an NPC record for sale. Keep `recordId` exclusively as the existing courier linkage.

## Terms and timing

Freeze these amounts when posting: B = existing basic reward; D = existing complete dossier total; **C = D + round(D × 0.50)**, clamped to the existing job-pay bound. Require C>D. If no higher valid bounded amount exists, post an ordinary v2 nonexclusive shadow job instead. Do not change B, D, global multipliers or the 900-second acceptance-relative deadline. Example only: B=420, D=630, C=945 UU. These are provisional first-playtest terms, not established economy balance.

Named standing effects, stored as fixed scenario tuning in `state.js`: honoring pays B or D and gives **Red Ledger +2** through existing completion; betrayal pays **C total**, gives **Red Ledger -5, Veridian Combine +2**, and forfeits all original payment and original completion rewards. Declining has **0 UU and no standing/contact changes**. Abandoning retains existing **Red Ledger -1**, 0 UU. Expiry/ordinary shadow failure retain 0 UU/no added standing. No fear, bounty, global war, NPC aggression event or other faction change is introduced. Existing general reactions to the resulting faction standing still apply and should be disclosed as ordinary standing effects.

Initial original offer and accepted terms name exclusivity, B/D/C, both docks, both factions, betrayal deltas, original forfeit, single-buyer rule, original deadline, abandonment consequence and automatic original filing on return. The rival offer becomes actionable immediately when `deep.state === ready`, before any original delivery; advertise it then via shared mission instruction and one commLine: “Complete dossier banked. Veridian Spire offers C total instead of Red Ledger's D. Selling there ends this assignment: Red Ledger -5, Veridian +2. Return to Ledger Anchorage to honor; docking there files automatically.” No rival message is emitted repeatedly on reload/ticks: emit only on the deep-ready transition, while projection always retains instructions.

This is deliberately an advertised buyer opportunity with a known delivery dock, not an unexplained omniscient live transmission or a second accepted job. No live courier location or hidden telemetry is disclosed. Full terms remain inspectable before acceptance, during pursuit, after completion and next to the buyer choice.

## Choices and state transitions

1. **Honor original:** return to Ledger Anchorage before deadline. Existing auto-file pays B if only basic is banked, D if dossier ready, Red Ledger +2 and existing local dockmaster rewards once. Any rival opportunity closes. Never suspend ordinary settlement awaiting an extra dialogue. Terms explicitly warn that returning commits this outcome.
2. **Decline buyer:** at Veridian Spire Jobs, after complete dossier, press **Decline Veridian; keep Red Ledger contract**. Close the buyer permanently for this assignment. Keep all evidence, deadline and original payment/return behavior. No immediate payment, standing or contact effects. Ignoring the buyer remains permissible and leaves it open until another terminal outcome.
3. **Betray:** at Veridian Spire Jobs, after complete dossier, press **Sell dossier to Veridian — C UU total; betray Red Ledger (-5)**. Adjacent full text includes Veridian +2 and loss of original D/+2/contact reward. One explicit click is the decision; no ambiguous “Accept” label or hidden extra consequence. Set original job terminal, consume the evidence and pay C once. Do not first accept a new job or move evidence into inventory. Original employer can never pay B or D afterward.

Decline and betrayal call one shared station mutation with exact own primitive args `{id, evidenceId, choice: 'decline'|'betray'}`. UI captures expected job object as an extra internal guard. Preconditions are exact shadow/v3/scenario/pairing, valid nested state, exact token, `job.state===accepted`, `progress===1`, deep ready, conflict open, time strictly before deadline, player alive, docked at Veridian Spire, Jobs service active, not jumping/berthHold/paused. Refuse stale, wrong-token, expired, wrong dock/service, old version, foreign/terminal/malformed job, basic/partial/closed dossier, extra/missing keys, repeated choice. No payment, standing, evidence, quote, target, deadline or unrelated-job mutation on refusal.

On betrayal validate all effects first, then synchronously set `conflict.state='betrayed'` and `job.state='failed'` (existing internal terminal convention) BEFORE emitting/noting/reward effects. Add C credits and only named standing deltas; call `noteJobOutcome(...,'betrayed',C)` and commLine; clear shadow projection and replace/release original job through existing shadow replacement. Never call generic completeJob, abandonJobDesk, applySpyExpose, rewardJobContacts or ordinary employer settlement in this branch. No dockmaster favor/trust at either dock is awarded for betrayal. Honor sets `honored` before its existing terminal effects. Request one coherent autosave after each successful choice/settlement; do not write an intermediate reward snapshot. Re-entrant ticks see a terminal row. Validate malformed runtime conflicts fail closed before any original payout as well as buyer payout.

Receipt copy is exact and shared with action result: “Sold <dossier reference> exclusively to Veridian Combine at Veridian Spire: C UU total. Red Ledger -5; Veridian Combine +2. Original contract closed without payment; no original completion/contact reward. No other contracts changed.” Honor receipt names actual tier, employer, actual total and ordinary +2/contact reward. Decline receipt says rival offer permanently closed, 0 UU/no standing change, original D and deadline retained. Existing bounded session jobState event records `outcome: betrayed` and `pay: C`; preserve current event field shape, no new persistence for logs. As today, comm/session history is not promised as an eternal cross-reload ledger; coherent credits/standing/jobs are persisted.

## Exact persistence and compatibility contract

No global save-version change, new job family/slot, top-level world field or new ctx event. Keep existing v1/v2 shadow parsing and fresh ordinary v2 path. Only qualifying newly posted conflict jobs use `shadow.v: 3`; all existing v2 fields retain their exact semantics and add exactly one plain object `shadow.conflict` with exactly these own keys:

| Key | Contract |
| --- | --- |
| `scenario` | Exact literal `ledger-veridian-dossier-v1` |
| `evidenceId` | Lowercase canonical UUID v4 (36 characters, strict regex including version/variant); generated once at posting using cryptographic random UUID source, retained through acceptance/reload. Never derived from job/courier ID, regenerated on load, or reused on repost. If UUID support unavailable, omit conflict and post ordinary v2; no insecure fallback. |
| `state` | Exact enum `open`, `declined`, `honored`, `betrayed`, `void` |
| `buyerPayQuoted` | Finite integer, existing payout bounds, strictly > deep.payQuoted; frozen from posted C, never recomputed on load or acceptance |

The UUID source is a new secure-context dependency: normal localhost dev/preview and HTTPS qualify; plain-HTTP LAN hosting may omit this scenario and produce ordinary v2 jobs. This compatibility limit is accepted for this bounded design and must be documented in release/test notes, not presented as random offer availability. Tests read generated tokens from internal jobs or inject a deterministic UUID factory in the harness; never hard-code a naturally random value. Add a missing/unavailable randomUUID fallback test proving ordinary v2 creation with no conflict/exclusivity copy, exception, or partial v3 row. The full token remains an internal stale-identity guard, not a secret capability or public action argument.

No duplicate source/buyer faction, system, expiry, risk, owner or boolean fields are persisted: scenario plus validated exact job origin/destination defines them. `open` includes the pre-dossier stage; derived eligibility controls availability, so completion needs no extra persisted offered flag. v3 requires nonlegacy deep support; offered means conflict open and existing fresh deep invariants; accepted allows open at any valid deep stage, declined only with deep ready/progress1; terminal `honored` requires progress1, `betrayed` requires deep ready/progress1, `void` covers expiry/loss/abandonment at any otherwise valid stage. Honored/betrayed/void require terminal failed/done job, never offered/accepted. Terminal rows are ordinarily removed by replacement; transient/serialized terminal payloads must still validate and never pay. EndShadowJob and explicit abandonment close any v3 conflict as void before replacement. Declined then expiry/abandonment becomes void. Every stepShadow/closeShadowDossier reconstruction must preserve the conflict object and v3, including warnings/pause/risk frames. Specifically replace the `stepShadow` version ternary `v: base.v === 2 ? 2 : 1` at `courier-shadow.js:885-895` with explicit v3/v2/v1 preservation and carry a copied `conflict` object alongside `deep`; `tickShadowFrame` assigns this reconstructed value to the job every frame. Pin this in a named `v3 survives flight reconstruction and reload` regression exercising active, paused, warning, basic-ready, pursuing and deep-ready frames.

Strictly validate a v3 shadow by existing v2 base/deep invariants plus the exact conflict rules and exact `originSystem=redmarch`, `destSystem=veridian`, subtype, job/record identity, finite accepted quote/deadline. Use a late second validation pass in `sanitizeOneJob`, after the existing `payQuoted` and `deadline` parsing at `save.js:660-671` and required-deadline checks. The earlier shadow call validates the v3 base/deep structure and conflict shape without claiming the deadline is available; the late pass receives the reconstructed job with validated id/recordId/origin/destination/state/progress/reward/payQuoted/deadline and checks the complete v3 contract. Reject the whole row if either pass fails. Do not weaken the finite accepted quote/deadline checks or revalidate against unchecked raw values. Reject unknown/missing nested keys, wrong prototypes, UUID shape, scenario/pairing, unknown versions, contradictory state/evidence, malformed/nonfinite amounts or unsupported legacy deep. Do not downgrade to payable v2/basic. v1/v2 with conflict stuffed into them also reject under their existing unknown-key rules. No retroactive conflict or exclusivity on valid earlier offered/accepted jobs, even if geographically eligible. Existing v1 accepted→v2 legacy migration stays intact.

Within a loaded save, duplicate v3 evidenceId across different rows is invalid: reject every colliding conflict row rather than choosing a payable winner; preserve all unrelated rows and credits/standing. Implement this as an unconditional rejection pass in `sanitizeJobs` over structurally valid rows, before duplicate-job-ID elimination and independent of all `dropJobsUntilCap` logic. It MUST reject accepted as well as offered/terminal colliding rows even when below the save cap; never copy the hunt/war cap-reduction pattern that protects accepted jobs. Existing duplicate job-ID handling then runs on surviving rows. Token collision is negligible in normal generation but malformed fixtures must not duplicate entitlement. This is single-job evidence ownership, not a global anti-cheat or external anti-rollback ledger. The same completed dossier is never copied/sold to both buyers; a new assignment produces a new dossier token.

Older game builds cannot read v3 jobs. Rollback uses prior code plus coherent pre-upgrade save backup, not a claim of downgrade-safe v3 loading. Old valid saves load unchanged under new code.

## Lifecycle and race rules

| Situation | Required result |
| --- | --- |
| Buyer offer stale after honor, decline, betrayal, replacement or restored other snapshot | Exact row/token/state guard refuses. ID reuse alone grants no entitlement. |
| Repeated UI activation/API call, tick or dock cycle | At most one terminal payment and one set of named deltas. Decline stays closed. |
| Original auto-file versus buyer | Mutually exclusive physical docks; first valid terminal transition wins. No pending settlement queue survives to a second dock. |
| Deadline reached while buyer pane open or at original dock | `now >= deadline` wins; zero payout, no betrayal. Choice returns expired; normal lifecycle closes it. No last-frame extension. |
| Partial dossier exposure/withdrawal/courier loss | Existing basic safety unchanged, buyer never available. Return basic normally. |
| Courier disappears after full dossier | Ready evidence remains; buyer still eligible until deadline or another terminal outcome. |
| Abandon at permitted Jobs desk | Existing -1 Red Ledger and 0 payout; destroy eligibility; no -5/+2 or contact effects. |
| Death/recovery or manual reload | Restore whole coherent snapshot (jobs, token, evidence, credits, standing); no import of newer receipts/choices/evidence. Pre-choice snapshot may restore choice AND previous finances together; post-choice cannot pay again. |
| Crash before completed autosave | Existing snapshot semantics; no promise of preserving unsaved frame. Never independent saves of credits versus entitlement. |
| Multiple accepted jobs | Only the named v3 job is terminalized; unrelated job state, progress, quotes, deadlines and contacts remain intact. Existing unrelated deadlines/progress may advance normally with time. |
