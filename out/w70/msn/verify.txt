BUGS

BUG 1  HIGH  persist / job ids  [implementable freeze is self-contradictory]

  Contract §0.11, §1.3 and brief merge table require EVERY job.id to pass
  live SAFE_ID.test (`/^[a-z0-9_]+$/i`, save.js:100) AND mining ids to match
  `^mine-[a-z0-9_]+-[0-9]+$` (hyphens).

  Live SAFE_ID rejects hyphens. Therefore:

    mine-freehold-0          FAIL SAFE_ID
    bounty-ace               FAIL SAFE_ID
    patrol-lane              FAIL SAFE_ID
    haul-provisions          FAIL SAFE_ID
    ferry-consignment        FAIL SAFE_ID
    bounty-pirate-*          FAIL SAFE_ID
    recovery-*               FAIL SAFE_ID

  If PR1 implements the table as written:

    - Mining cards never survive restore (career cannot persist).
    - Unique four are "invalid". §1.2 also says never drop them, then says
      empty-after-drop → ensureJobs rebuilds offered uniques. That wipes
      accepted/done haul-ferry-ace-patrol. Boot-test restore of
      ferry-consignment (scripts/boot-test.mjs ~6124, 8192) would fail.
    - Accepted pirate/recovery overlays vanish.

  Security review claimed this pair as the __proto__ fix and did not notice
  SAFE_ID cannot accept the hyphen prefix it also froze.

  Fix direction (for a later design patch, not this verifier): do not run
  raw SAFE_ID on the full hyphenated job id. Allowlist live unique ids;
  mining: prefix + SYSTEMS-key middle token + RESERVED_IDS; drop __proto__ /
  mine-__proto__-0. Or use underscores (mine_freehold_0) and still exempt
  today's hyphenated unique/overlay ids.

BUG 2  MEDIUM  persist cap vs slot law

  MINING_SLOTS_PER_SYSTEM = 2 on a global world.jobs array.
  SYSTEMS has 6 authored + 94 generated = 100 keys (state.js:500–541,
  galaxy.generated.js header). Docking around the map can accumulate
  200 offered mining rows plus unique four plus pirate/recovery.

  JOBS_SANITIZE_MAX = 64 drop order (invalid → done mining → done pirate/
  recovery → other done) never drops offered mining or accepted jobs.
  After ~30 systems the cap cannot be applied without violating "never
  drop accepted" or silently deleting offered remote mining (then
  syncMiningJobs would refill on next visit, but that is not written).

  Marked "proposed, needs owner" but still a hole: 2-per-system persist
  and cap 64 cannot both be true galaxy-wide.
