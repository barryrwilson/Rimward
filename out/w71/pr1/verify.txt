## Bugs found

### Bug 1 — omitted `world.jobs` on the snapshot keeps live session jobs
- Severity: medium
- Contract: `out/w70/msn/shared-contract.md` §1.2. If `world.jobs` is missing, not an array, or empty after drop → leave `[]` (then `ensureJobs` in `station.js` reseeds the unique four). Same restore pattern as omitted `fieldOre` (`save.js` 703–704 deletes the live bag).
- Worker claim: missing lists become `[]`. Security review check “Non-array / missing jobs → []” is not true for an omitted key.
- Repro:
  1. Build `ctx` with live `world.jobs` that already sanitizes (for example unique four, or the stale ace used in `edge-probe.mjs`).
  2. Call `restore(ctx, { v: 1, world: { currentSystem: 'freehold' } })` with no `jobs` key.
- Expected: `ctx.world.jobs` is `[]` so station `ensureJobs` can seed the unique four.
- Actual: `restore` only copies `WORLD_FIELDS` when `snap.world[k] !== undefined` (`save.js` 698–700). Omitted `jobs` leaves the live array. `sanitizeJobs` then heals that live array, not an empty list.
- Evidence: `out/w71/pr1/edge-probe.log` — `omit.jobsEmpty: false`, `omit.staleDropped: false`. `omit.jobsIsArray: true` because the stale live list survived.
- Contrast: `jobs: null` / `{ not: 'array' }` / `[]` do heal to `[]` (worker probe + empty edge).
- Why it matters: a berth/autosave blob with no `jobs` key (legacy or stripped) loaded into a live session keeps the current board instead of healing missing data. Boot with `world.jobs === undefined` still becomes `[]` inside `sanitizeJobs`, so boot-only missing is fine.
- Suggested fix (do not apply in this verify pass): in `restore`, if `snap.world.jobs === undefined` set `ctx.world.jobs = []` (or delete, then let `sanitizeJobs` turn non-array into `[]`), next to the `fieldOre` omit delete.

No other restore-heal bugs found in the extra edges above.
